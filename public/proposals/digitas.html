02Our Understanding
A Rakhi campaign is a sprint, not a marathon.

This campaign has a hard, immovable deadline: Raksha Bandhan falls on Friday, 28 August 2026. Rakhis are purchased and gifted in the 2–3 weeks before the festival, so traffic won't spread evenly — we expect 80%+ of all QR scans in a short, intense burst around Rakhi week, with a sharp peak on the festival day itself as siblings exchange rakhis and scan together.

Our proposal is engineered for exactly this shape of demand:

  • Serverless architecture that scales from near-zero to thousands of concurrent users automatically — no capacity planning, no idle-server cost before or after the peak.
  • A 28-day plan with a built-in buffer, so the experience is live, tested, and stable well before rakhis reach consumers' hands.
  • A single-provider Gemini pipeline — Gemini 2.5 Flash for warm, language-mirrored greeting text; Gemini's Nano Banana for unique, character-consistent comic-style artwork per user — one provider, one bill, tuned for the sibling, memory-driven prompt space.
  • A card experience that always delivers — every user gets a beautiful card every time, even if the image model rate-limits or fails. No error screens during the brand's biggest moment of the year.
03The AI Comic Card Engine
Illustrated, per user.

The end-screen card is a unique, illustrated comic-style piece — sibling characters, memory-driven panels with captions, festive Rakhi styling. Delivering this authentically requires image generation per user, not static templates.

3.1 · Model choiceWhy Nano Banana (Gemini 2.5 Flash Image)

Character coherence

The same sister/brother characters appear coherently across multiple panels of one card — critical for the comic format, and Nano Banana's standout capability. Alternative models struggle here.

Speed

~4-second image generation, so the total perceived wait from "Creating your one-of-a-kind greeting…" to reveal stays in the 6–8s range — magical, not slow.

Cost

At roughly ₹3 per generated card, the image API is by far the largest recurring cost driver — broken out transparently and billed at actuals.

Multi-panel

Handles multi-panel composition natively — the whole comic layout in one generation — keeping cost to one API call per card, not three.

3.2 · The generation pipelineFrom memory to card in four steps
01

Prompt orchestration (Gemini)

Gemini 2.5 Flash reads the memory and inputs, then builds an optimized image prompt — pulling out the moment, mood, and visual beats ("2 AM Maggi cooking," "whispered secret"). It also writes the greeting text and panel captions.

02

Image generation (Nano Banana)

The optimized prompt plus a fixed style guide ("warm storybook illustration, festive Rakhi palette, sibling characters, comic-panel layout") generates a unique branded card image in ~4 seconds.

03

Branded framing

The illustration is composited server-side into a branded frame — top banner ("Happy Raksha Bandhan!"), Real Greetings logo, closing tagline, share/download CTAs — at print quality (PNG + JPG).

04

Safety & fallback

Every step is monitored: prompt version, latency, output pass/fail. Failed images trigger one automatic retry, then a graceful fallback to a curated illustrated template personalised with the user's name — no error state, ever.

3.3 · Content safetyTwo-stage screening for imagery

Image generation introduces safety considerations beyond text. Our pipeline uses two-stage screening: (1) user-input screening before generation (rejecting abusive, unsafe, or PII-heavy memories), and (2) automated visual safety checks on the output, plus prompt-level constraints that steer the model firmly toward warm, family-friendly, festive imagery. Nano Banana also has strong native safety behaviour.

05AI Architecture — Details
Secure, tunable, bilingual.
  • Secure pipeline — all AI calls are server-side; API keys never reach the browser. Inputs are validated and sanitised before generation.
  • Configurable prompts — both text and image prompt templates are editable via configuration without code deploys, so tone and visual style can be tuned mid-campaign. All prompt versions are logged per generation.
  • Language mirroring — the greeting mirrors the language of the user's memory: a Hinglish memory yields a Hinglish greeting. A major emotional-quality win for a Rakhi audience, at no extra cost.
  • Two-stage moderation — input screening before generation; visual and text safety validation on outputs; fallback to a curated template card if either check fails or generation times out.

06Data Privacy & Consent
Compliant with the DPDP Act, 2023.
  • Explicit consent — unticked-by-default, with linked Terms & Privacy Policy before any PI is captured; consent timestamp and policy version stored per record.
  • Encryption — all PI (name, mobile/email if enabled, relationship, memory text) encrypted in transit (TLS 1.3) and at rest (AES-256).
  • Data minimisation — contact fields enabled only if the campaign requires them; memory text and generated cards retained for campaign duration + 30 days by default, then purged.
  • No AI training on data — processing via commercial APIs (Anthropic, Google) with no training on submitted data, per commercial terms.
  • One-click export — CSV/Excel export of captured leads with consent status for the brand team.

10C · Important noteOn image API costs
  • Volume-driven & pass-through — image AI is the largest single variable and is passed through at actuals. At ₹3/card, 35,000 cards ≈ ₹1,05,000 in image API cost alone.
  • Cost optimisation — Google offers Batch API pricing at ~50% off for non-realtime workloads. Real-time generation uses standard pricing; we can enable batch mode for pre-warming, retries, and admin-only regeneration to reduce cost.
  • Budget cap (included) — for a hard image-AI cap (e.g., ₹75,000/month), we implement a fallback-to-template mode that activates automatically as the cap approaches — users still get a beautiful card from a curated library. Included in base scope as a configurable toggle.
